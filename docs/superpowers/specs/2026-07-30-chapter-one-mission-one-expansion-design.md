# 第一章第一关扩容与单位可读性设计

> 日期：2026-07-30
> 适用分支：`codex/battle-camera-composition`
> 状态：已确认设计，待实施

## 1. 目标

把第一关“初次接触”从可在约 3 回合内完成的短教学关，升级为标准难度约 25 至 35 分钟、10 至 15 回合的正式战术任务。扩容必须增加路线、时机、阵型和风险选择，不能只增加移动距离、敌人生命或无意义等待。

同时解决以下视觉问题：

- 单位被缩在圆形底座中，整体观感接近棋子。
- 当前镜头强制显示完整地图，地图越大，单位越难看清。
- 玩家职业和敌人类型的差异主要依赖红蓝配色，轮廓、武器和体型差异不足。

## 2. 当前问题证据

- `ch1_m1` 的锁定地图为 14×10，共 140 格。
- 标准配置只有 2 名玩家、3 名初始敌人和 1 名增援。
- 地图元数据写明 `activate_terminal + reach_evac`，但关卡类型是 `extract`。运行时 `MissionObjectiveState` 对 `extract` 只检查全员进入撤离区，终端不参与胜利条件。
- 当前相机在启动时计算全图适配缩放；角色纹理最大显示尺寸为 56px，实心圆形阵营底座半径为 25px。
- 已完成的一次真实鼠标流程在 3 回合内胜利，证明当前任务长度不足。

## 3. 采用方案

采用“三阶段战术任务”：

1. 侦察渗透：三人小队从南侧进入，通过西、中、东三条路线接近东部数据终端。
2. 终端固守：激活终端后上传持续 2 个完整敌方回合，警报触发夹击增援。上传范围内必须至少有一名存活玩家单位，否则进度暂停但不倒退。
3. 交叉撤离：上传完成后，西北侧撤离区开放，队伍需要横穿战场完成撤离。

可选资源箱位于西侧支路。绕路收集可获得额外信用点和三星条件贡献，但会延长路线并增加被包夹风险。

## 4. 关卡数据

### 4.1 地图规模与布局

- 固定尺寸：18×14，共 252 格，比当前增加 80%。
- 玩家出生区：南部中央 3 个互不重叠格。
- 数据终端：地图东部中段。
- 撤离区：地图西北侧，上传完成前不可计入胜利。
- 资源箱：地图西侧中段支路。
- 路线：至少声明 3 条 `route_anchors`，分别代表掩体密集的西路、距离最短但暴露的中路、具有高地和侧射角的东路。
- 掩体密度：可通行格中的 18% 至 28% 为半掩体或全掩体；任何唯一通路不得被阻挡。
- 地标：至少 3 个，覆盖南部部署识别、东部终端识别和西北撤离识别。

### 4.2 队伍与敌军

- 玩家编制：3 人，使用初始阵容中的突击、狙击和重装职业。
- 初始敌军：5 人。
- 初始编成：2 名基础哨兵、1 架侦察无人机、1 名敌方狙击手、1 名突击无人机。
- 第一波增援：终端激活时从南东侧进入 2 人，形成后方压力。
- 第二波增援：上传完成时从北部进入 1 人，阻断最短撤离路线。
- 标准难度同时存活敌人上限：7。
- 标准难度全场增援上限：3。

敌人不能生成在玩家占用格、撤离核心格或不可通行格。找不到配置位置时使用现有安全生成搜索；仍无位置则跳过该单位并记录 warning，不允许覆盖单位。

### 4.3 回合与评级

- 标准难度最大回合：18。
- 标准难度目标通关区间：10 至 15 回合。
- 三星回合目标：11 回合。
- 剧情难度最大回合：23，目标区间 8 至 13。
- 困难难度最大回合：15，目标区间 11 至 15。
- 首回合敌人继续保持被动，避免新玩家在理解界面前受到惩罚。
- 第一关继续禁用物品与警戒，教学重点限定为移动、攻击、掩体、终端交互、固守和撤离。

三星要求同时满足：零阵亡、11 回合内完成、收集资源箱。未收集资源箱不阻止胜利。

## 5. 任务状态机

新增第一关可复用的阶段状态，不把阶段判断散落在 HUD、地图和胜利检查中。

状态依次为：

- `approach`：终端尚未激活。
- `upload`：终端已激活，上传计数进行中。
- `evacuate`：上传完成，撤离区正式开放。
- `complete`：所有存活玩家单位位于撤离区。

地图数据提供以下配置：

```json
{
  "mission_flow": {
    "terminal_required": true,
    "upload_turns_required": 2,
    "upload_hold_radius": 1,
    "evac_locked_until_upload": true,
    "optional_resource_credit": 150
  }
}
```

状态转换规则：

- 玩家单位相邻终端并消耗 1 AP 后，从 `approach` 进入 `upload`。
- 每次敌方回合结束时，如果至少一名存活玩家单位位于终端曼哈顿距离 1 以内，上传进度加 1。
- 上传进度达到 2 后进入 `evacuate`，触发撤离提示和第二波增援。
- `approach` 或 `upload` 阶段进入撤离区不会胜利。
- `evacuate` 阶段所有存活玩家单位进入撤离区后胜利。
- 全部玩家阵亡或超过回合上限时失败。

HUD 始终显示当前阶段和数字进度，例如“上传数据：1/2，保持终端控制”。状态变化通过已有目标更新信号传递，HUD 不自行推断任务阶段。

## 6. 事件增援

`EnemyDirector` 增加命名事件入口，支持地图脚本使用以下触发：

```json
{
  "trigger": {"type": "event", "name": "terminal_activated"},
  "action": "spawn_reinforcement"
}
```

第一关使用两个一次性事件：

- `terminal_activated`：生成第一波 2 人增援。
- `upload_completed`：生成第二波 1 人增援。

事件只触发一次，并继续服从 `max_reinforcements` 与 `enemy_cap`。现有按回合触发方式保持兼容。

## 7. 可选资源目标

地图中的 `resource` 对象成为真实交互目标：

- 玩家移动到资源格或其正交相邻格后，可点击资源对象并消耗 1 AP 收集。
- 每个资源对象只能收集一次。
- 第一关资源箱在胜利结算时增加 150 信用点，并记录到战斗结果。
- 失败、重试或退出战斗不得提前写入存档奖励。
- HUD 显示“资源箱：已收集”或“资源箱：未收集”。

资源收集状态由任务状态对象持有，结算只读取最终结果，不直接访问地图节点。

## 8. 战术镜头

大地图不再以“启动时完整显示”为默认目标。

- 默认缩放：1.0，允许范围 0.65 至 1.5。
- 开局焦点：三名玩家出生点的中心。
- 滚轮：以鼠标位置为中心缩放。
- WASD 和方向键：持续平移。
- 鼠标中键拖动：按住时拖拽地图。
- 屏幕边缘 16px：产生平滑边缘平移；设置菜单的“减少动态效果”不禁用平移，只禁用镜头震动。
- `Home`：回到当前选中单位；无选中单位时回到小队中心。
- `Tab`：短暂切换到全图总览，再次按下恢复此前缩放与位置。

相机必须受地图边界和 HUD 安全区域约束。默认镜头不需要显示完整地图，但任何地图边缘都必须可通过平移到达。

## 9. 单位视觉

### 9.1 美术方向

制作第一关正式角色小样，使用透明 PNG、3/4 俯视角、清晰头肩和武器轮廓：

- 玩家突击：宽肩深蓝装甲，青色面罩，突击步枪横向轮廓。
- 玩家狙击：细长灰蓝轮廓，长枪明显超出身体宽度。
- 玩家重装：大体型深蓝装甲，重机枪和背部弹药模块。
- 基础哨兵：红黑人形装甲，短步枪。
- 侦察无人机：四翼或菱形飞行轮廓。
- 敌方狙击手：瘦高红黑轮廓，长枪和单侧光学模块。
- 突击无人机：前倾机身和双侧武器，明显区别于侦察无人机。

源图由项目允许的 AI 图像生成工具独立生成，处理流程和最终资源登记到 `AI_RESOURCES_STATEMENT.md` 与 `RESOURCE_MANIFEST.md`。正式运行时资源不得包含文字、水印、烘焙背景或不透明棋盘格。

### 9.2 运行时呈现

- 源图工作尺寸至少 512×512，最终运行时裁切为 96×96 透明 PNG。
- 普通单位艺术最大显示尺寸：76px。
- 重装单位最大显示尺寸：82px。
- Boss 保持独立尺寸规则。
- 删除普通单位的大面积实心圆底座。
- 保留脚下椭圆软阴影、2px 阵营色脚环、选中外环、HP/护盾/AP 信息。
- 玩家与敌人的识别不能只依赖颜色；灰度预览下仍应能根据体型和武器区分。
- `UnitSprite.z_index` 随单位所在行更新，使 3/4 俯视角色发生垂直重叠时前后关系正确。
- 角色移动、攻击、受击、技能和死亡状态继续使用现有程序动画；新纹理必须通过全部状态契约。

## 10. 教学与反馈

第一关教程顺序调整为：

1. 移动与镜头。
2. 攻击与掩体。
3. 终端交互。
4. 上传固守。
5. 撤离。

教程仍可跳过并记忆。玩家跳过教程后，HUD 目标和地图标记仍必须完整表达任务要求。

关键阶段反馈：

- 激活终端：屏幕顶部显示警报提示，镜头短暂聚焦第一波增援入口。
- 上传暂停：HUD 使用黄色文字提示“终端无人控制，上传暂停”。
- 上传完成：撤离区域常驻高亮，镜头聚焦撤离区后返回当前单位。
- 资源收集：显示奖励数值并播放独立 SFX。

## 11. 测试与验收

### 11.1 自动化

- 锁定地图精确为 18×14，三人出生、五名初始敌人、三条路线、终端、资源箱和撤离区完整。
- 所有出生点、事件增援点、终端和撤离区可达且互不非法重叠。
- `approach -> upload -> evacuate -> complete` 状态转换逐步验证。
- 未激活终端、上传未完成或上传区域无人时不能胜利。
- 两个事件增援各触发一次，并服从总量和在场上限。
- 资源奖励只在胜利结算时发放一次。
- 默认镜头缩放为 1.0，出生区位于 HUD 安全区域内，地图四边可平移到达。
- 中键拖动、滚轮、Home 和 Tab 的状态转换有输入契约。
- 普通角色纹理为 96×96、带 Alpha，显示上限不少于 76px，无实心棋子底座。
- 发布门禁原有全部套件继续通过，不允许降低断言或删除旧覆盖来换取通过。

### 11.2 窗口化验收

使用全新存档、标准难度、真实鼠标键盘完成第一关：

- 记录开始与结束时间，目标为 25 至 35 分钟。
- 记录回合数，目标为 10 至 15 回合。
- 实际执行终端激活、两回合固守、两波增援、可选资源和全员撤离。
- 检查三条路线至少两条具有不同的掩体和射线选择。
- 在 1280×720、1920×1080 和 2560×1440 下检查单位可读性、HUD 遮挡和镜头边界。
- 截取部署、终端固守、交叉撤离三张画面，确认角色不再呈现为圆形棋子。
- 导出 Windows EXE/PCK 并运行现有包验证器。

如果首次真人通关低于 20 分钟，优先增加路线压力、敌方位置和阶段事件，不增加普通敌人生命。若超过 40 分钟，优先缩短上传或撤离距离，不删除阶段选择。

## 12. 非目标

- 不在第一关开放物品、警戒、复杂技能树或基地管理教学。
- 不为延长时长增加随机刷怪、无限增援或高生命敌人。
- 不重写整个战斗框架或替换 Godot 场景体系。
- 不把第一关扩容直接复制到其余五关；后续关卡根据人工数据单独平衡。
- 本轮只制作第一关实际出现的角色小样，不批量重做全游戏所有单位。
