# 文档与资源记录政策

> status: Active
> owner: 项目负责人
> updated: 2026-07-31

## 目的

文档必须帮助开发者判断“现在真实可运行什么、下一步做什么、如何验证”，而不是把设想、数据目录或旧审计结论误写成完成事实。

## 文档职责

| 位置 | 职责 |
|---|---|
| `README.md` | 仓库入口、当前范围和常用链接 |
| `tactical-grid/README.md` | 本地运行、测试与目录说明 |
| `tactical-grid/PROJECT_STATUS.md` | 带日期的实测快照 |
| `docs/PROJECT_TAKEOVER_ROADMAP.md` | 任务、优先级、验收和阻断项 |
| `docs/design/README.md` | 活跃首发设计范围 |
| Git 历史 | 已删除的旧设计、一次性审计与失效假设 |

## 生命周期元数据

活跃规格和路线图应声明：

- `status`：Draft、Approved、Active、Frozen baseline、Superseded 或 Archived。
- `owner`：维护责任人。
- `updated`：最后一次事实核验日期。
- `applies_to`：适用范围。
- `supersedes`：取代的旧文档或基线。
- `superseded_by`：后继文档。

README 和状态页是派生摘要，不得拥有高于源代码、不可变 QA 或批准规格的权威级别。

## 完成状态规则

只有同时满足以下条件，文档才能将功能标为完成：

- 实现已经接入真实场景或流程。
- 已运行与该功能相关的自动测试或可复现手动验证。
- 结果、日期和已知限制已记录在路线图或状态快照中。
- 若功能使用资源，资源已接入、导入无误且可追溯来源。

JSON 条目、空场景、未连接按钮、未使用图片、未导出构建和仅有脚本的功能均不构成完成。

## 资源与许可证记录

每项进入游戏的外部、开源、AI 生成或程序化资源必须有清单记录，至少包含：

| 字段 | 要求 |
|---|---|
| 最终路径 | 游戏内实际引用的文件 |
| 类型 | AI 生成、程序化、自有或开源 |
| 来源 | 工具、仓库、作者或生成脚本 |
| 许可证 | 名称、版本和适用说明 |
| 修改 | 去背、裁切、切图、动画、调色或转码 |
| 用途 | 场景、角色、UI、特效或音频触发 |
| 验证 | 尺寸、Alpha、导入、运行截图或音频试听 |

来源不明、带水印、无法确认商用/修改权利，或未完成游戏内验证的资源不得进入发行版本。

## 归档规则

- 活跃工作树不设置文档归档目录；已失效且不再执行的文档直接删除，历史由 Git 提交记录保留。
- Git 历史中的旧文档不可以作为功能完成、发行范围或当前技术路径的证据。
- 新结论优先补充或更新现有活跃入口，不新建同职责路线图、派发表或完成度报告。
