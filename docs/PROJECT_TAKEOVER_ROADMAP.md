# Tactical Grid 成品化总路线图

> 状态：Active
> 负责人：项目负责人

> 唯一开发基线：`main`

## 1. 唯一目标

把 Tactical Grid 完成为普通玩家无需 Godot 编辑器、无需 Node 服务、无需外部说明即可启动、理解、完整游玩并正常结束的 Windows 单机战术游戏。

当前开发不是继续堆叠已有 Demo 功能，而是先把第一章重做成真正有辨识度的正式游戏切片：

> 观察已侦测敌人的意图，争夺战术网络节点，控制摄像头、门、炮塔、电力和增援信标，用战场本身击破敌军计划。

第一章通过真人验收后，才按同一生产标准扩展第二至第五章。自动化通过、数据条目存在或资源文件生成，都不等于玩法和内容已经完成。

## 2. 当前事实基线

### 2.1 已验证

- Godot 4.7.1 项目可启动，主场景为 `res://scenes/boot.tscn`。
- 当前客户端已有主菜单、基地、战斗、对话、教程、设置、暂停、结算和六关流程。
- 2026-07-31 重新运行 `client/tests/run_release_gate.ps1`：2,639/2,639 断言通过，0 失败，3 条预期 warning，0 条非预期 warning/error。
- 任务单一权威、行动接口、地图校验、迷雾状态、敌方意图状态、战术网络和警戒系统已进入 `main`。
- M1 已实现 18×14 单人开场、摄像头救出侦察兵、7 名总敌人、最多 3 名同时活跃、终端上传和撤离。
- 当前数据规模包括 30 张地图、68 个技能、23 件武器、18 件物品、20 个敌人数据类型和 5 个 Boss 数据类型。
- 第一章已有四套环境组件、单位图、HUD 图标、对话数据和 32 个程序化 WAV，可作为重设计素材库。

### 2.2 不能据此宣称

- 2,639 条自动化断言不能证明输入直观、战术有趣、地图好探索或六关平衡。
- 导出预设和构建脚本已纳入版本控制，但尚未完成干净克隆和干净 Windows 账户验收。
- M1 是重设计后的开发中垂直切片；M2-M6 仍是旧内容基线。
- 服务端依赖尚未安装，本轮 `npm run build` 因缺少 `tsc` 未执行成功；服务端测试数字只能作为历史记录。
- 现存资源数量不能证明角色区分、动画、音频听感和场景独特性已经达标。

### 2.3 当前发布判断

**No-go。**

当前版本可以称为“新设计可运行开发基线”，不能称为第一章发布候选版，更不能标记为 1.0 正式游戏。

## 3. 文档与证据权威顺序

发生冲突时按以下顺序判断：

1. 当前源代码、场景、资源、配置和本轮实际命令输出。

3. 已批准设计规格和架构决策记录。
4. 本路线图中的活跃任务和验收标准。
5. `PROJECT_STATUS.md` 与 README 等派生摘要。
6. 许可证、隐私和资源清单等独立合规门。

所有活跃规格应声明 `status`、`owner`、`updated`、`applies_to`、`supersedes` 和 `superseded_by`。归档文档不再承担当前完成度或任务优先级。

## 4. 已批准的产品边界

### 4.1 第一章保留

- 离线单人、方格回合制、移动额度加 2AP。
- 六个手工制作任务和明确的章节 Boss。
- 四个正式可部署角色：突击、狙击、重装、侦察。
- 战争迷雾、最后已知位置、已观察敌方意图。
- 战术网络节点和五类设施：摄像头、门、炮塔、电力、增援信标。
- 事件驱动警戒、任务/情报/小队三项结算徽章。
- 基地、成长、设置、存档、失败重试和章节结局。

### 4.2 第一章明确不做

- 独立黑客小游戏或新的战斗货币。
- 逐回合回退、完整战斗快照和刷随机数读档。
- 两回合倒地救援、永久死亡和复杂伤员系统。
- 升降桥、移动平台和程序随机主线地图。
- 大型装备词条、随机掉落和库存整理。
- 实时潜行、时间线预测系统或大规模可破坏场景。
- 为了显得内容多而同时部署大量角色或堆叠敌人生命。

### 4.3 操作基线

- 左键选择、移动、攻击和设施上下文操作。
- 右键取消，`Esc` 暂停。
- `Tab` 切换下一名可行动队员。
- `Space` 保留结束回合，不再与网络显示冲突。
- `G` 切换战术网络显示，`Home` 聚焦当前单位。
- 总览使用另一个可重映射按键，不与 `Tab` 冲突。
- 普通安全移动和主武器攻击直接执行；只有明确风险行为需要一次确认。
- HUD 同时只给出当前最重要的三个信息层级。

## 5. 第一章内容目标

### 5.1 章节结构

| 任务 | 正式定位 | 主要新内容 | 首次目标时长 |
|---|---|---|---:|
| M1 回声失联 | 单人潜入后营救侦察兵 | 基础操作、观察、摄像头节点、撤离 | 15-20 分钟 |
| M2 熄灯协议 | 三人切断能源封锁 | 电力、炮塔、盾卫、路线选择 | 20-25 分钟 |
| M3 断轨营救 | 抢救目标并改变列车路线 | 首个明确倒计时、工程师、警戒射击 | 20-25 分钟 |
| M4 囚笼密钥 | 三选四小队渗透监区 | 门控网络、侦察兵、临时盟友 | 25-30 分钟 |
| M5 反向猎杀 | 敌军主动反夺网络 | 猎手、失联区域、节点防守取舍 | 25-30 分钟 |
| M6 零号终端 | 三阶段网络 Boss | 多节点控制、污染、熔毁终局 | 30-35 分钟 |

### 5.2 M1 硬门

M1 是全部后续内容的生产样板，未通过真人测试前不得批量重做 M2-M6。

- 约 22×16，三个紧凑遭遇区，不以空走扩大地图。
- 阿尔法单人开场，前段找到侦察兵后双人行动。
- 全场 7-9 名敌人，同时活跃不超过 3 名。
- 只教学选择、移动、攻击、观察、接管和结束回合。
- 每 3-5 分钟出现新信息、路线、敌人组合或任务阶段。
- 首次接管摄像头必须立即改变玩家可见信息和决策。
- 不开放物品、完整警戒、复杂技能和全部基地系统。
- 1280×720 下地图必须占满战术视区，不得出现大面积无意义黑区。

### 5.3 章节趣味性门

- 每个遭遇区至少有两条有效处理路线。
- 每关至少两次设施操作改变路线、视野、敌人计划或增援。
- 正式路线不得连续四回合只有安全移动。
- 每种敌人必须改变玩家优先级，而不只是生命和伤害不同。
- 每名角色缩成灰度后仍可从体型、武器、姿态和装备认出。
- Boss 三阶段必须要求不同决策，不能只增加伤害和生命。

## 6. 技术架构路线

### 6.1 必须保留和复用

- `GridSystem`、`Pathfinding`、`VisionSystem` 的基础几何能力。
- `TurnManager`、`MissionObjectiveState`、`EnemyDirector` 的事件触发基础。
- `TacticalTile`、`UnitSprite`、镜头和目标预览已有表现。
- 现有战斗公式、效果系统、存档迁移和设置系统中通过测试的部分。
- 客户端锁定地图作为正式关卡权威；Node 地图生成器保留为开发工具。

### 6.2 必须重构

- `BattleController` 只负责协调，不再复制目标、网络、警戒和可见性状态。
- `MissionObjectiveState` 成为唯一任务状态权威。
- 行动统一为“查询/预览 -> 校验 -> 提交”，避免移动、攻击、技能各走不同执行路径。
- 引入稳定实体 ID 和单一可注入 RNG，为保存、回放和确定性测试打基础。
- 客户端与开发工具共享版本化地图模式和校验器。
- AI 规划与执行分离，只公开玩家当前观察到的意图。
- 战争迷雾必须是状态系统，不是单纯遮罩特效。

### 6.3 新增系统边界

- `TacticalNetworkState`：节点、连接、设施状态和一次性接管脉冲。
- `VisibilityState`：未探索、已记录、正在观察和最后已知位置。
- `EnemyIntentState`：生成和发布可公开的敌方意图。
- `AlertState`：接收具名事件并提供下一等级后果。
- `MissionObjectiveState`：任务阶段、主目标和可选目标。
- HUD 只显示状态并发送请求，不推断战斗规则。

## 7. 美术、UI 与音频生产

### 7.1 可复用资源

- 四套环境包共 108 个环境组件。
- 当前 AI/程序化单位、目标物、HUD、状态、VFX 和背景资源。
- 现有对话肖像作为风格和构图小样，先修正角色键和运行时接线。
- 现有 32 个程序化 WAV 作为音色基线，不直接冒充最终听感完成。

### 7.2 第一章最低新增集

- 四名玩家角色轮廓和职业色饰重制。
- 协议工程师、猎手两套新敌人；清理旧敌人纹理复用别名。
- 网络节点四状态和五类设施状态图标。
- 敌方意图、节点状态、风险与警戒的统一图形语言。
- 选择、接管、过载和设施反转的 VFX 动画表。
- 六关各一个主地标，避免相同组件换色。
- 可商用、适合简体中文的正式 UI 字体及许可证。
- 网络扫描、接管、禁用、过载、警戒升级、设施反转等至少 8 个新 SFX。
- 至少 3 个可循环战斗音乐层和胜负/阶段转换短句。

### 7.3 制作门

任何批量资源先完成一个 M1 遭遇区小样，并验证：

- 源文件、生成方式和许可证有记录。
- 尺寸、Alpha、切图、导入过滤和缩放正确。
- 1280×720 与 1920×1080 下可读。
- 灰度和色觉缺陷模式下仍能区分阵营、职业和状态。
- 动画、碰撞、音频并发和游戏内触发真实接入。
- 未接入运行时的文件不计入完成资源。

## 8. 存档、发布与合规

- 第一章采用遭遇区边界检查点，不实现逐回合回退。
- 0 HP 单位在本任务中失去行动能力，第一章不永久死亡。
- 保留当前整数星级存档字段，UI 映射为“任务/情报/小队”三个徽章，避免无必要存档重写。
- 修复损坏主存档恢复后可能覆盖健康备份的问题。
- 对高于当前版本的未来存档只读拒绝，不静默回写。
- `export_presets.cfg` 必须纳入版本控制并去除机器私有路径。
- 构建脚本与验证器必须使用同一个输出目录和文件名。
- 发布包必须包含 README、隐私说明、第三方通知、Godot MIT 文本、Godot `COPYRIGHT.txt`、资源清单和 SHA-256 清单。
- 第一章候选版使用 0.x 版本号；五章完整并通过发布门后才使用 1.0。

- 每关时长、回合、倒地、重试、警戒峰值、节点使用和放弃原因。
- 1280×720 与 1920×1080 完整流程。
- 两小时长时运行，持续内存增长低于 10%，无输入或音频失效。

## 11. 模型与工具分工

| 工作 | 推荐执行者 | 强度 |
|---|---|---|
| 架构拆分、AI 意图、确定性、存档、最终整合 | Sol | xhigh |
| Godot 输入、HUD、镜头、地图模式、关卡接入、测试 | Terra | high/xhigh |
| 数据清理、资源清单、重复契约测试、文档同步 | Terra 或通用代码模型 | medium/high |
| 角色、敌人、地标、肖像与视觉小样 | ImageGen + 图像处理工具 | 每批先小样 |
| 音频母带、并发、混音与长循环 | 音频工具 + 人工试听 | 技术检查后人工 |
| 趣味性、操作理解、色觉、听感、最终发布 | 真人玩家与项目负责人 | 必须人工 |

模型强度不能替代真人试玩。Sol xhigh 用于高耦合和高风险工作，不应用在可以由数据校验或重复脚本完成的任务上。

## 12. 参考设计的取舍

- Into the Breach：借鉴已知威胁和通过位移改写敌方计划，不复制确定性解谜结构。
- Tactical Breach Wizards：借鉴角色能力组合和可选角色挑战，不在第一章实现逐回合回退。
- Invisible, Inc.：借鉴信息、观察范围和风险升级，不做实时潜行。
- Mario + Rabbids：借鉴清楚的角色轮廓和小队协同，不做自由移动战场。
- Gears Tactics：借鉴能产生行动链的正反馈，不引入处决 AP 复制系统。
- Phantom Brigade：借鉴敌方计划预览，不引入时间线编排。
- Showgunners：借鉴手工遭遇事件，不采用直播秀题材或随机导演替代关卡设计。
- Door Kickers 2：借鉴可理解的多路线和队伍职责，不引入实时暂停规划。
