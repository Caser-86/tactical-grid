# M1 首次玩家测试协议

版本：`M113 / 1.0`
目标：验证一名完全不了解 V1/V2 的玩家能否在没有口头指导的情况下理解并完成 M1。

## 1. 测试边界

- 测试对象只使用 V2 的新档和标准难度，任务为“找到失联侦察兵并一起撤离”。
- 每名玩家使用匿名编号 `P01`、`P02` 或 `P03`，不记录姓名、账号、机器名、设备 ID、IP、操作系统用户或其他系统隐私。
- 不得把项目负责人自测计入三名首次玩家样本。
- 录屏是可选项。不同意录屏时，仍必须保留事件表和问卷结果。
- 测试者可以报告技术故障，但测试主持人不得解释操作、目标、颜色、攻击范围、敌方意图或地图路线。

## 2. 测试前准备

1. 使用本分支当前构建和新的 V2 存档，不读取 V1 存档或已有攻略。
2. 将屏幕设置为窗口化 1280×720，关闭开发者日志和调试覆盖层。
3. 为该场测试分配一个匿名编号，启动本地 `V2PlaytestRecorder`。
4. 先向测试者说明：“请像第一次玩一样自行尝试，看到什么就做什么；如果不明白，请直接说出来。我们不会提示你怎么操作。”
5. 若测试者同意录屏，先取得同意再开始计时；不同意则只记录事件和口述卡点。

## 3. 观察规则

- 主持人只记录，不做引导，不用鼠标替玩家点击，不代替玩家读出目标含义。
- 测试者连续 20 秒没有动作、明确询问“该做什么”、或重复同一无效操作两次，记一条 `stuck_marked`；仍不得提示。
- 只有崩溃、窗口无法操作、输入设备失效等技术故障可以由主持人处理，并在表格中单独标记为技术干预。
- 记录测试者的原话时尽量逐字记录，不把主持人的解释写成玩家理解。

## 4. 必记时间点

以 `session_started` 为零点，记录下列事件的相对秒数：

| 检查点 | 记录条件 |
|---|---|
| 首次选择 | 玩家第一次选中突击兵 |
| 首次移动 | 玩家第一次提交有效移动 |
| 首次攻击 | 玩家第一次独立提交攻击 |
| 蓝/红范围 | 玩家能说出两种范围分别代表什么 |
| 敌方箭头 | 玩家能说出箭头表示敌方下一步意图 |
| 迷雾揭示 | 玩家移动后主动注意到周边信息更新 |
| 营救 | 侦察兵加入编队 |
| 撤离 | 玩家和侦察兵进入撤离区并完成任务，或触发失败 |
| 结束 | `mission_completed`、`mission_failed` 或玩家主动结束 |

## 5. 记录器事件

允许的事件只有：

`session_started`、`unit_selected`、`move_committed`、`attack_committed`、`hint_shown`、`stuck_marked`、`scout_rescued`、`mission_failed`、`mission_completed`、`session_ended`。

事件只保存相对耗时、事件序号和玩法字段，例如单位 ID、坐标、提示 ID、卡点原因、失败原因。任何包含姓名、机器名、账号、邮箱、IP 或设备字段的 payload 都必须被拒绝。记录器的默认输出位置为：

```text
user://playtests/m1/P01.json
user://playtests/m1/P02.json
user://playtests/m1/P03.json
```

文件只留在本地，不自动上传；汇总时复制到未纳入 Git 的 `artifacts/v2/verification/h1/`。

## 6. 通过标准

三名玩家都完成真实测试后，负责人填写 `H1_SUMMARY.md`：

- 三人都没有得到口头操作指导。
- 每人 30 秒内知道应选择突击兵。
- 每人 90 秒内完成首次移动。
- 每人 3 分钟内独立完成首次攻击。
- 每人能解释蓝色范围、红色范围和敌方箭头。
- 每人观察到移动后迷雾立即揭开。
- 每人能营救侦察兵并撤离，或失败后独立重试。
- 首次流程接近 12-18 分钟；超出时写明具体卡点。
- 至少两人选择愿意继续 M2。
- 没有人因攻击方式、攻击范围或结束回合永久卡住。

全部满足时写入 `decision: PASS`。任一条不满足时写入 `decision: FAIL`，并列出返回 M114 的最小修正任务；不得由 AI 代写玩家结论或伪造 PASS。
