# 第一章战斗正式美术切片设计（历史规格）

## 目标

把第一章战斗从代码绘制的占位棋盘转换为可发布的、可读的 2D 战术场景。
首个可玩切片必须真实替换资源，而非在截图中叠加概念图。

## 范围与顺序

第一阶段只交付并验收以下资源与绑定：

| 类别 | 首批资源 | 游戏内位置 |
| --- | --- | --- |
| 地图 | 数据区地面、道路、金属掩体、货物掩体 | 第一章战斗网格 |
| 任务物件 | 数据终端、撤离信标 | `steal_data`、`extract` 任务 |
| 单位 | 突击兵俯视精灵、攻击无人机俯视精灵 | 玩家和敌人单位层 |
| 特效 | 弹道、命中火花、小型爆炸 | 攻击与命中反馈 |
| UI | 移动、攻击、技能、物品、警戒图标 | HUD 与行动菜单 |

通过首批验收后，按相同规格扩展狙击、重装、医疗、侦察、其余敌人、Boss、角色立绘和全部章节环境。

## 视觉规范

- 视角：严格俯视，单位朝上偏右，地块正交 64 x 64 像素。
- 风格：干净的半写实科幻战术插画，不模拟任何商业游戏的专有角色、界面或标识。
- 颜色：冷青蓝环境；玩家青蓝识别边；敌人朱红识别边；目标使用高亮青绿；危险使用橙色。
- 可读性：单位精灵主体不得小于 42 x 42 像素；不可含文字、水印、拼图边界或透明棋盘背景。
- 资源格式：PNG、RGBA、透明背景；所有文件名 ASCII；原图保留在 `assets/generated/chapter1/source/`，游戏使用的裁切图位于 `assets/generated/chapter1/runtime/`。

## 生成与处理流程

1. 使用 Codex 内置图像生成创建单一、无文字、无水印的素材原图；透明素材先用纯色键控背景生成。
2. 将原图复制到项目源资源目录；使用本地键控去背工具生成 RGBA PNG。
3. 裁切并缩放到运行时规格，检查四角 alpha、边缘色溢出、像素尺寸和 Godot 导入。
4. 在 `RESOURCE_MANIFEST.md` 记录提示词、生成日期、工具、用途、路径和许可状态；旧 SDXL 文件继续排除在发布包之外。
5. 在场景中使用 `Sprite2D`、`AtlasTexture` 或 `TextureRect` 绑定资源。程序绘制仅可保留为开发期资源缺失回退，发布构建不得命中回退。

## 代码边界

- 新增 `ArtCatalog` 或等价的轻量资源映射，负责 terrain、blocker、objective、unit、effect 的路径和兜底报告。
- `TacticalTile` 从直接 `draw_*` 转为使用图块精灵；地形逻辑、碰撞和网格坐标不变。
- `UnitSprite` 保留血条、AP 和选中状态，但主体轮廓改为图像精灵。
- `TacticalEffect` 以序列帧或缩放淡出纹理替代几何线条，保留现有事件接口。
- HUD 行为、任务数据、存档和战斗数值不在本切片中改动。

## 验收与测试

1. 无头测试检查所有正式资源存在、可由 Godot 加载、尺寸与 alpha 合法，且旧参考目录仍被导出排除。
2. 场景测试载入第一章战斗，断言玩家、敌人、掩体、终端、撤离点和攻击效果均绑定正式纹理。
3. 以 Per-Monitor DPI 感知截图在 720p 和 1080p 检查无裁切、无水印、无遮挡 UI，单位阵营与任务物件一眼可辨。
4. 连续启动、进入战斗、攻击、结束关卡三次，无 Godot ERROR、无资源缺失、无节点泄漏。
5. 仅在上述验收通过后，批量制作后续职业、敌人和章节资源。

## 非目标

- 不使用现有 `assets/characters/`、`assets/effects/`、`assets/tiles/`、`assets/ui/` 中带水印或来源不充分的图片。
- 不在首批资源未验证前生成整套 30 关资产。
- 不为美术替换重写战斗规则、任务逻辑或数值。
